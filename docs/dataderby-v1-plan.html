The source contract

One request shape.
Nine combinations.

GET /statisticsfeed/1/getteamstatistics ?stageId=25662 &category=summaryteam &subcategory=all category summaryteam | defensive | offensive subcategory all | home | away

The page load supplies Model-last-Mode, the token the feed requires. A bare request returns HTML.

Nine

Three sections × three splits = nine feed calls per stage. One page load per competition; the token works across stages.

How a gate is detected

  1. Strip the byte-order mark and decode UTF-8.
  2. Parse JSON. It must succeed.
  3. Require teamTableStats, paging, statColumns.
  4. Require statColumns to equal the expected list for that section and split.
A 200 response with an HTML challenge is a gate. A 403 is a block. A second consecutive gate stops the run. Detection is never by byte size.
A missing key is written as NULL, never as zero. A rate is stored at full precision.

Ruled out

Keying on season_key (a typo relabels a season) or tournamentName (a cosmetic change splits it).

The stage model

Stages are identity,
not labels.

CodeMeaning

whoscored_stage_id is identity. Labels are display text from the page's #stages selector; the registry declares the stage ids. A label is never used in a key or a join; the id is.

The registry declares the stages. config/stages.toml lists every stage the season is expected to have. A missing stage is a configuration error, not an empty result.

Order is not chronology. The selector order is not the calendar order, and the label Final Stage means the knockout phase, not the final match.

Separate

The fixture calendar is a different source. v1 joins nothing to WhoScored by team name; there is no crosswalk.

has_league_table gates the standings fact. It never gates the team fact.

Two clocks

The source has no
clock. We do.

ClockMeaningSet from
observed_atWhen we began reading this statemin(captured_at) over the page and the nine feeds
accepted_atWhen the cohort became queryableCommit time

observed_at is an interval. The header stores capture_span_seconds = max(captured_at) − min(captured_at). A span over 180 seconds is retried: a sweep that slow is no longer a plausible single state.

observed_at orders history. It is the key for latest state, deltas and reports. accepted_at only records when the transaction committed; a backfill can have an older observation with a newer acceptance.

Reports pin (tournament_id, whoscored_season_id, whoscored_stage_id, observed_at). They never pin snapshot_id or accepted_at.
No source timestamp means “the source was late” can only be inferred from our observation times.

The latest-state trap

A missing team must
disappear, not fall back.

WRONG — maximum time per fact row

select f.* from fact_team_snapshot f join competition_snapshot s using (snapshot_id) where s.observed_at = ( select max(s2.observed_at) from fact_team_snapshot f2 join competition_snapshot s2 using (snapshot_id) where f2.team_id = f.team_id and s2.whoscored_stage_id = s.whoscored_stage_id );

A team missing from the newest snapshot still has an older row, so it reports a state that is no longer true.

CORRECT — pick the snapshot first

select f.* from fact_team_snapshot f join ( select snapshot_id from competition_snapshot where tournament_id = $1 and whoscored_stage_id = $2 order by observed_at desc, snapshot_id desc limit 1 ) s using (snapshot_id);

The snapshot is chosen once. Every team comes from that snapshot, and only that snapshot.

Proof

Delete one team from the newest snapshot. It must not reappear from an older one.

Snapshot identity

The id is a name.
The edge is the guard.

snapshot_id = ULID() parent = last accepted snapshot_id for this stage by observed_at, or 'genesis' UNIQUE (parent_snapshot_id, content_fingerprint) UNIQUE (tournament_id, whoscored_season_id, whoscored_stage_id, observed_at)
The measurement. 24 cases, three implementations, 500 publishes, a real process kill, a contending writer, and a rebuild with one backfilled observation. The ULID costs +6.2% storage at 300 snapshots. Timing is not the deciding factor.

What the edge gives us. A retry that sees the same content under the same parent inserts nothing. A revert A → B → A has a different parent from the first A, so it is recorded as a new state.

What the id does not give us. It is not reproducible. A rebuild is content-equivalent, not id-equivalent. Nothing outside the warehouse may store it.

Limits

Report address is the stage triple plus observed_at. content_fingerprint is not unique on its own. The single-writer lock is still required.

The parent is the last accepted state by observed_at, not by accepted_at. A backfill must not become the newest state.

The operating rules

One writer.
Raw first. Fail legible.

Concurrency

One writer

Many fetchers are fine; one loader. dataderby run takes data/state/pipeline.lock before touching the database. A second writer exits with code 5. A stale lock is broken only when the PID is dead and the lock is older than 15 minutes.

Evidence

Raw is the record

The database can be rebuilt; the source cannot. Write every payload before parsing, with exclusive create. A sidecar records URL, status, content type, bytes, SHA-256, capture time and client version. Nothing under data/raw is ever rewritten.

Failure

Three actions

BLOCK refuses the cohort, keeps raw, exits non-zero and does not advance the checkpoint. RETRY treats the state as a mid-publish signature. WARN records and continues. “Ambiguous” is not an action.

The lock is a process lock. It is released by the operating system when the process dies, so there is no stale-lock daemon.

Ownership

One owner
per column.

MetricOwnerAgreement rule

Why this matters. Two sections publish the same number. If the loader takes whichever arrived first, a mid-publish disagreement becomes a silent value. The owner rule turns that into a retry.

Rule

Exactly one owner per column. Shared metrics are asserted equal, not averaged.

The 60-column contract is reproduced by a test that counts the columns, not by a test that trusts this slide.

The run · 1 of 2

Steps 1 to 7.

01

Lock. Take data/state/pipeline.lock. If another writer holds it, exit 5.

02

Load config. Read config/stages.toml and open an ingestion_run row in running.

03

Load the page. Read the HTML, the Model-last-Mode token, the stage labels and the three standings views. Its capture time is one input to observed_at, which is the minimum across the page and the nine feeds.

04

Probe. Fetch summaryteam/all first. Record its hash. If PROBE_SKIP is on and the hash matches, stop. In v1 the branch is disabled.

05

Fetch the other eight. Sequential, at least 1.2 seconds apart, three tries, backoff 2/4/8 seconds with jitter. A second consecutive gate stops the run.

06

Write raw. Every payload is written atomically with exclusive create, plus a sidecar and a raw_capture row.

07

Parse. Nine feeds become 20 × 60 candidate rows; three standings views become 30 measures per team. Missing values are NULL.

—

Shape checks. A3, A4, A13, A15, A8 and the standings shape checks A17, A18, A19, A21 run before the fingerprint.

The page is one request per competition, not per stage. The token works across stages. The nine feed calls are per stage.

The run · 2 of 2

Steps 8 to 13.
Then recovery.

08

Fingerprint. Canonicalise the candidate and the standings. content_fingerprint covers both facts.

09

Publish gate. If the fingerprint equals the checkpoint's last committed fingerprint, mark no_change and exit 0. No rows are written.

10

Begin. Open the transaction.

11

Assert. A1, A2, A5, A6, A7, A9, A10, A16, A20. Any failure rolls back and stops.

12

Insert. Header with ON CONFLICT (parent, content) DO NOTHING; if inserted, 20 team rows and the standings rows; update the checkpoint.

13

Commit. Mark the run accepted. Exit 0.

Crash recovery. At start, a run still marked running with a committed snapshot is reconciled to accepted. A run that crashed before commit has no snapshot and is marked abandoned. The retry reuses the same parent and content, so the unique edge prevents a duplicate.
BEGIN insert header ... on conflict do nothing returning id if inserted: insert 20 facts + standings update checkpoint COMMIT
No COMMIT in a finally. A constraint error aborts the transaction; the explicit rollback is required.

Canonicalisation

Same content.
Same bytes. Always.

rows sorted by team_id keys sorted floats via repr() (shortest round-trip) None as null UTF-8, newline-joined, no trailing newline

Included: team_id, all 60 measures, the three standings views in overall, home, away order, tournamentId and isOpta.

Excluded: paging, name, presentation order and seasonId. They carry no meaning for the state.

Versioned: canonical_version is stored on the header. A change to this function is a new version, not a silent rehash.

Risk

Float repr is stable in practice, not guaranteed by the language. The golden hash catches a change rather than hiding it.

A row reorder or a dict-key reorder must not change the fingerprint. A single measure change must change it.

The limit on the tin

Season-to-date
movement, not
match events.

“How did the table move?” is a true question. “What happened in match 7?” is not.

Given shotsPerGame and apps, you can form shots ≈ shotsPerGame × apps. That product is exact only for the cumulative value.

Differencing two cumulative products double-counts the rounding of apps. The home and away splits have a different denominator per team.

README

What the data can and cannot answer belongs in the README, not a footnote. This limit is part of the product.

The source is a cumulative season-to-date table. It is not a match feed and cannot be made into one by subtraction.

What would make us abandon

The findings that
change the plan.

E2 fails

The table is unchanged while details move.

The probe is useless. The design survives, but the schedule must be full sweeps and the cost model in the decks does not.

E4 fails

Team ids are not stable across seasons.

Identity needs a name-based crosswalk sooner than planned, and the deferred dimension stops being optional.

Licence

The decision is withdrawn.

v1 becomes an offline exercise over the captured evidence, and M5 and M6 change shape entirely.

Source

It stops publishing cumulative tables.

The snapshot premise is wrong. The plan should be discarded, not patched into a match feed.

These are not edge cases. They are the assumptions the plan is built on.

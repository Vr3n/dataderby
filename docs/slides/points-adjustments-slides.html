ACT I · THE WRONG FIX

An identity can be a constraint,not a definition.

Ten words this deck will use.

ACT II · THE SHAPE

The model is three layers,not three copies.

sourcefeed payloadJSON inside the site's page.
storedfact_standings_snapshotpoints_overall = 20. The reported value.
computedv_points_adjustmentsreported 20 · expected 24 · −4.
what the view does

It joins the snapshot header to the standings fact, computes 3 × won_overall + drawn_overall, and subtracts. It filters to rows where the reported total is below the maximum.

what the view does not do

It does not store a row of its own. There is no second points column to drift. Delete the view and the fact is still correct.

A view is a lens, not a ledger.
ACT II · THE SQL

The view computes the gap;it does not store a second truth.

ACT III · THE LEDGER

A migration ledger isthe database's memory.

the rule

Each file is applied once. Its bytes are hashed. If the bytes change, migrate() refuses to run.

the question it answers

“What is this database running?” Not “what is in the folder?” The folder can change; the ledger is the record.

Live table: schema_migration · full SHA-256 is stored; twelve characters shown here.
ACT III · WHY

Immutability is what makesthe ledger useful.

reproduce

Same bytes, same state

A rebuild on another host applies the same files in the same order. A changed file would make two databases disagree while both claim the same version.

audit

What ran, and when

The ledger records the version, the checksum and the timestamp. An incident review can reconstruct the exact contract the database was running.

evolve

Add, don't rewrite

A new rule is a new file. The old file remains the record of what was applied. Nothing is deleted to make the new state look inevitable.

the sentence to remember
A migration is a deployment unit, not a draft.
The ledger is strict because the alternative is a database that cannot explain itself.
ACT III · THE BYTE FAILURE

The ledger hashes bytes,not meaning.

LF · the applied file
0d21c51f4943

≠

cebfbad5fa70

what changed

Not the SQL. A checkout on Windows applied core.autocrlf=true and rewrote every line ending.

the fix

*.sql text eol=lf in .gitattributes. One representation on every host.

A text diff hides this. The checksum does not.

ACT III · THE ALTERNATIVES

Every shortcut had the same flaw:it rewrote history.

alternativewhy it fails
Edit 002 and update the ledgerThe ledger becomes a note about the past that anyone can edit. It no longer proves what ran.
Exempt assertions from the checksumThe contract becomes the one migration that can change under a live database — the exact failure the ledger prevents.
Move assertions out of migrationsIt orphans the applied 002 row and creates a second deployment path for one contract.
Normalise text before hashingThe hash no longer describes the bytes that were executed. The ledger becomes approximate.
the accepted alternative

Append a new file, load the whole set, reject duplicates, and force LF. The ledger stays honest and the contract still grows.

The strict option is the one that keeps the audit trail usable.

ACT V · THE LESSON

What this teaches aboutdata engineering.

01 · modelling

Reported ≠ derived

Store the source value; compute the expectation beside it. A derived column that overwrites the source destroys evidence.

02 · grain

Scope follows grain

A deduction belongs to the overall table, not to both splits. Checking the wrong grain creates duplicate events.

03 · contracts

WARN ≠ BLOCK

Not every anomaly is a failure. The action is part of the rule: report legitimate events, block impossible ones.

04 · deployment

Migrations are immutable

An applied file is a deployment unit. Grow the contract by adding files, not by rewriting what ran.

05 · reproducibility

Bytes, not text

LF and CRLF are different bytes. A checksum sees the difference even when a diff looks identical.

06 · testing

Properties beat examples

Generate the inputs. Assert the invariant. The SQL and the definition cannot drift silently.

If you remember one: report the gap, do not rewrite it.
ACT V · OPEN ITEMS

The honest limits.

no_change

Assertions are skipped

If the content fingerprint is unchanged, publish returns before A22 runs. The deduction is still in v_points_adjustments; it will not re-print a warning until the content changes.

tooling

No query command yet

The view is queryable with DuckDB, but there is no dataderby adjustments command. Add it when an operator asks.

scope

Overall only

A deduction applied to home and away splits would need a separate rule. The current model treats it as an overall event.

transport

Browser token race

One live dry run failed with “page did not expose gSiteHeaderValue”; the retry succeeded. Unrelated to this change, still tracked.

Limits are part of the design, not an omission from the slide.

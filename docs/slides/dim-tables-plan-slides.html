The problem, team side

Arsenal exists twice.
The name is copied twice.

snapshotteam_idteam_name
snap_d90c (EPL)13Arsenal
snap_535f (UCL)13Arsenal
37 clubs look like this: Liverpool, Man City, Bayern, Real Madrid, PSG, and 32 more.

The name whoscored_team_name is stored 258 times for 221 clubs. Today that is harmless. A statsbomb_id column would copy the mapping 258 times too, with no constraint stopping snapshot one from saying 87 and snapshot two from saying 89.

Rejected · statsbomb_id on the fact

258 copies, zero guarantees

Breaks on the third source, repeats every mapping per snapshot, and permits one WhoScored id to point at two StatsBomb ids.

Rejected · team_snapshot

Same grain, second copy

One row per team per snapshot is the fact grain again. It stores no new information, only another copy of the name.

The fix

One row per club in dim_team. One mapping row per source in team_source_key. Facts keep their columns and gain one canonical id.

37 clubs in two stages each, verified by grouping fact rows on whoscored_team_id across stage ids.

Eleven stage addresses live in headers and checkpoints today. Forcing StatsBomb season ids into header columns hides the equivalence decision. A mapping row records it where reviewers can see it.

Chosen · dim_stage + mapping

One canonical row per stage

dim_stage names the stage once. stage_source_key records how each source addresses it. A split or merge is a new mapping row, not a migration.

Lineage stays

Headers keep every whoscored_* column. The raw archive still rebuilds everything, per ADR 0004.

The UCL knockout and Championship playoff stages are not scheduled yet, so the mapping starts one to one and grows.

The proposal

Four small tables.
Facts keep everything.

dim_team221 rows, PK canonical id
team_source_key221 rows, whoscored first
facts+ dataderby_team_id
viewsjoin canonical name
dim_stage11 rows, PK canonical id
stage_source_key11 rows, whoscored first
header+ dataderby_stage_id
viewsjoin canonical name
dim_team

One row per club

Canonical id, canonical name, first seen, updated at. Backfill: 221 rows from live facts.

dim_stage

One row per stage

Canonical id, tournament, season, stage code, canonical name. Backfill: 11 rows from live headers.

Two key maps

One row per source

PK on (source, source ids) stops duplicates. UNIQUE on (canonical id, source) stops double mapping.

Full DDL in ADR 0011. Migration files 006 and 007, one table family per file.

The DDL, team side · sql/006

The mapping is the
constraint.

CREATE TABLE dim_team ( dataderby_team_id VARCHAR PRIMARY KEY, canonical_name VARCHAR NOT NULL, first_seen_at TIMESTAMPTZ NOT NULL, updated_at TIMESTAMPTZ NOT NULL ); CREATE TABLE team_source_key ( dataderby_team_id VARCHAR NOT NULL REFERENCES dim_team, source VARCHAR NOT NULL, source_team_id VARCHAR NOT NULL, PRIMARY KEY (source, source_team_id), UNIQUE (dataderby_team_id, source) );

Backfill: 221 dim rows, 221 key rows with source = 'whoscored'. StatsBomb rows arrive with source two.

RuleWhat it stops
PK (source, source_team_id)the same WhoScored id mapping to two clubs

Names are stable today. A rename updates canonical_name and updated_at. Validity columns arrive only with the first real rename.

The DDL, stage side · sql/007

Name the stage once.
Map every address.

CREATE TABLE dim_stage ( dataderby_stage_id VARCHAR PRIMARY KEY, tournament_name VARCHAR NOT NULL, season_key VARCHAR NOT NULL, stage_code VARCHAR NOT NULL, canonical_name VARCHAR NOT NULL, UNIQUE (tournament_name, season_key, stage_code) );
CREATE TABLE stage_source_key ( dataderby_stage_id VARCHAR NOT NULL REFERENCES dim_stage, source VARCHAR NOT NULL, source_tournament_id VARCHAR NOT NULL, source_season_id VARCHAR NOT NULL, source_stage_id VARCHAR NOT NULL, PRIMARY KEY (source, source_tournament_id, source_season_id, source_stage_id) );

Each migration file is independent. If 007 fails, 006 still stands and facts still publish, because the canonical columns stay nullable until cutover.

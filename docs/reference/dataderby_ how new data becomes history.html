How new data becomes history

Data flow, snapshot storage, and three edge cases. Press Next or the right arrow to step through.

One capture, five steps, one snapshot

The sweep saves the source answer as a raw file. Nothing is changed. Raw files only grow.Parse turns the raw file into typed rows. We can redo this step from the raw file at any time.Validate checks the whole cohort. If one check fails, we reject it and keep the evidence.Publish writes the header and all team rows in one transaction. All or nothing.Only now does the checkpoint move. A crash before this line means a safe retry.

History is stored by adding rows, never by editing

Example data. Each snapshot holds every team. Three teams shown.

Snapshot S1 arrives. Three rows are added.S2 arrives. Three new rows go under S1. S1 is not touched.S3 arrives. The table only grows. A retry cannot overwrite a row.“Latest” is a view. It picks the newest accepted snapshot, then reads its rows. Old snapshots stay for history.

Edge case 1: only one team’s numbers change

S1: a full snapshot of 20 teams.S2: still 20 rows. 19 rows repeat the old values. We copy them, so every snapshot is a complete cohort.One team changed, 10 → 13 points. The delta view shows only that team. The extra rows cost a few KB.

Edge case 2: two matches end 5 minutes apart

Match 1 and match 2 finish 5 minutes apart. The fixture list tells us these times.Naive: one sweep per match. That is 2 sweeps, 18 requests. The source publishes both results together anyway.Better: merge both end times into one window. Wait the grace time after the last end. Then run one sweep, 9 requests.If the source is late, retry a few times, then stop. We log “source late”. No endless polling.

Edge case 3: a result is revoked

Example: Team A beat Team B 2–1. Later the match is voided.

S1 and S2 are accepted. S2 counted the match: +3 points, +2 goals for A.S3 shows the old totals again. We add S3 as a new snapshot. S2 stays as it was. We never edit it.The delta is negative. A running total should not go down. So we flag it as a correction, not as a new match.Latest shows S3. History keeps S2. We can still show that the match was counted and then revoked.
